Sillage {{ .Chart.AppVersion }} deployed — release “{{ .Release.Name }}” in {{ .Release.Namespace }}.

Follow startup (migrations run before the port opens):
  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "sillage.fullname" . }}

1. CREATE THE FIRST ACCOUNT
   No account exists at first startup, and no environment variable creates one:
   the first created account is an administrator.
   The command is interactive, hence -it:

     kubectl -n {{ .Release.Namespace }} exec -it deploy/{{ include "sillage.fullname" . }} \
       -- node /app/server/cli/user-create.js

2. ACCESS THE INTERFACE
{{- if .Values.ingress.enabled }}
     http{{ if .Values.ingress.tls.enabled }}s{{ end }}://{{ .Values.ingress.host }}
{{- else }}
     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "sillage.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
   then http://127.0.0.1:{{ .Values.service.port }}
{{- end }}

3. INSTALL AND AUTHENTICATE AGENT CLIS
   CLIs (claude, codex) are not in the image: install through the interface
   on the first new-conversation screen. They go into the data volume
   and survive pod replacement. Then authenticate inside the pod:

     kubectl -n {{ .Release.Namespace }} exec -it deploy/{{ include "sillage.fullname" . }} -- bash

BACK UP: <data>/secret.key encrypts all saved secrets and git credentials.
Losing it makes them permanently unreadable, even with an intact database.
{{- if and .Values.storage.data.enabled (not .Values.storage.data.storageClass) }}

WARNING: storage.data.storageClass is unset, so the PVC silently used the
cluster default StorageClass. If it is NFS, SQLite will eventually corrupt:
WAL locks are unreliable there. Check the selected class and specify block
storage if needed:

  kubectl -n {{ .Release.Namespace }} get pvc {{ include "sillage.fullname" . }}-data \
    -o jsonpath='{.spec.storageClassName}{"\n"}'
{{- end }}
