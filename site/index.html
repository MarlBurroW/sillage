What runs where.

Sillage runs on a machine you choose and drives the agents’ own CLIs there. Your projects and conversations stay on that machine, and the agents reach their providers the way they always do.

  1. Your screens

    The Desktop window, or a browser on your laptop, phone or tablet.

  2. Sillage

    Desktop on your computer, or Server on a host you control. Projects, conversations, the board and memory live in its local database.

  3. The agents’ CLIs

    Claude Code, Codex, OpenCode, Grok Build, Antigravity and Copilot CLI run on the same machine, in your Git repositories.

  4. Their providers

    Each CLI signs in with your account or API key and calls its own provider. Sillage is not a proxy and has no model of its own.

Before you install.

Something missing or unclear?

Open an issue
Is Sillage free?

Yes. Sillage is free and open source under the MIT license. You bring the accounts, subscriptions or API keys your agents require. There is no Sillage subscription.

Does it replace my coding agents?

No. Sillage runs the native Claude Code, Codex, OpenCode, Grok Build, Google Antigravity and GitHub Copilot CLI tools. They keep their own capabilities and permission flows, and share one interface for your projects and conversations.

What do I need before installing?

For Desktop, the app and Git: macOS has it with Apple’s Command Line Tools, Windows needs Git for Windows, and the Linux .deb installs it. For Server, a Linux host with systemd or an Apple Silicon Mac, with curl, tar and Git; the installer brings Node.js if needed. Then install the agent CLIs from Sillage’s settings and sign in with your accounts.

System requirements
Where do my code and conversations live?

Sillage stores its workspace on the computer or server you choose. Your agents still talk to their configured AI providers: hosting Sillage yourself doesn’t make those models local. OpenCode can use local models when its providers support them.

Does Sillage collect data about me?

No. There is no telemetry, analytics or crash reporting, and nothing about you or your code goes to its author. Sillage does contact a few services on its own, such as GitHub to check for updates; the security page lists each one, and when.

What Sillage sends, and when
Can I use it from my phone?

Yes. Open Sillage Server in your phone’s browser, or enable Remote access in Desktop, which uses Tailscale. Desktop has to stay open; Server runs as a service. In both cases the host must stay awake. Push notifications are available in the Server edition.

Can I share my server with a team?

Server supports several accounts and shared projects for people you trust. Agents run under the same system account, so it is not an isolated environment for untrusted users. Put it behind a VPN or a protected HTTPS address. Remote access guide

How do updates work?

Desktop checks GitHub for a new release when it starts and every four hours, downloads it in the background, and installs it when you choose Restart and update. Server updates from Settings › About or by running the install command again, and keeps the two previous versions on disk. With Docker, pull a newer image.

How mature is Sillage?

Young, and moving fast: 53 releases since July 2026, each listed with its notes. Much of Sillage is built from inside Sillage, so its everyday paths get constant use. Bugs and rough edges go to GitHub issues.

Why Sillage exists

“I wanted one place, on a server I own, where I could pick up a project from my phone, without carrying a laptop or keeping track of a dozen terminals.”
MarlBurroWCreator of Sillage

I also wanted to keep the agents I already used. Sillage runs their native tools and gives them a shared workspace: projects, a board, instructions and memory. A session can look up an earlier decision and leave context for the next agent, even when I switch CLIs.

Claude Code and Codex wrote most of Sillage, much of it from inside Sillage itself, often from a phone.
