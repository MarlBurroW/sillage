Configuration requise

L’application embarque son propre serveur et son runtime Node.js. Git est la seule chose à installer toi-même, sauf avec le .deb, qui l’installe.

macOS
macOS 13 Ventura ou version ultérieure, sur Apple Silicon. Git est fourni avec les Command Line Tools d’Apple.
Windows
Windows 10 ou 11 sur x64. Installe Git for Windows : Sillage et Claude Code utilisent son Git et son Bash.
Linux
x64 ou arm64, sur Ubuntu 22.04, Debian 12 ou une distribution plus récente.
Agents
Installe les CLI depuis l’application, puis connecte-toi avec tes propres comptes. Un CLI déjà installé sur l’ordinateur est pris en compte.
Mémoire
Sillage lui-même demande peu. Chaque session en cours consomme ce dont son CLI a besoin : une session Claude Code prend 400 à 500 Mo.

Avant le premier lancement

Les applications ne sont pas encore signées, et Sillage a besoin de Git. Pour chaque système, une ou deux choses à savoir.

macOS : Git et l’autorisation à la première ouverture

Déplace Sillage de l’image disque vers Applications. Installe les Command Line Tools d’Apple si Git manque. L’application n’est pas encore notarisée ; au premier lancement, macOS peut demander de passer par Réglages Système › Confidentialité et sécurité › Ouvrir quand même.

Guide d’installation sur macOS
Windows : Git et SmartScreen

Installe Git for Windows, puis lance l’installeur de Sillage. L’installation se fait par utilisateur. L’application n’est pas encore signée, donc SmartScreen peut afficher un avertissement au premier lancement ; le guide explique l’étape Informations complémentaires › Exécuter quand même.

Guide d’installation sur Windows
Linux : choisir le paquet

Sur Debian ou Ubuntu, utilise le paquet .deb : il installe Git et le profil AppArmor dont le bac à sable de Chromium a besoin sur les versions récentes d’Ubuntu. L’AppImage est prévue pour les autres distributions. Choisis x64 ou arm64 selon ton processeur.

Guide d’installation sur Linux
Accéder à Desktop depuis ton téléphone

Active l’accès privé par Tailscale dans les réglages « Accès distant » de Desktop. L’application doit rester ouverte et l’ordinateur hors veille.

Sillage Server

Installe Sillage sur un hôte que tu contrôles. Le service en arrière-plan garde les agents au travail quand tu fermes le navigateur, tant que l’hôte reste hors veille.

Une commande sur l’hôte

Pour Linux avec systemd, ou macOS sur Apple Silicon. Lance-la dans le terminal de l’hôte.

Lis l’installeur avant de le lancer 
curl -fsSL https://raw.githubusercontent.com/MarlBurroW/sillage/main/install.sh | bash

  1. Installe sur ton hôte

    L’installeur prépare le runtime et le service en arrière-plan.

  2. Ouvre ton espace de travail

    La visite guidée du premier lancement crée ton compte et connecte tes agents.

  3. Connecte tes appareils

    Utilise Tailscale ou une adresse HTTPS protégée, en suivant le guide d’accès distant.

Configuration requise

L’installeur les vérifie d’abord et te dit ce qui manque.

Systèmes
Linux sur x64 ou arm64 avec systemd, WSL2 compris, ou macOS sur Apple Silicon.
Outils
curl, tar et Git. Node.js 22.14 ou plus récent est utilisé s’il est présent ; sinon, l’installeur télécharge Node.js 24 LTS dans le dossier propre à Sillage.
Réseau
Sillage écoute sur 127.0.0.1, port 7317. Pour y accéder, passe par Tailscale, un VPN ou un reverse proxy HTTPS.
Conteneurs
Une image pour amd64 et arm64 sur ghcr.io/marlburrow/sillage, et un chart Helm dans le dépôt.
Mémoire
Environ 110 Mo pour Sillage, plus 400 à 500 Mo par session Claude Code en cours.

Desktop ou Server

L’espace de travail est le même. Ce qui change, c’est où il tourne et comment tu y accèdes.
