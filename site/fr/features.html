Conversations

14 fonctionnalités

Tout ce qui entoure une conversation, du premier prompt à l’agent suivant.

Six agents de code natifsUtilise Claude Code, Codex, OpenCode, Grok Build, Google Antigravity et GitHub Copilot CLI dans un même espace de travail.

Sillage lance les CLI propres à chaque agent, avec tes comptes et tes outils. Leur activité est présentée de la même façon, tandis que les modèles, les permissions, les commandes natives et l’import d’historique suivent ce que chaque CLI prend en charge. Les forks de conversation suivent aussi l’intégration : Antigravity et Copilot démarrent une nouvelle session avec un contexte portable. Consulte le guide agent par agent.

Conversations qui te suiventFerme le navigateur, reviens plus tard et reprends le fil depuis un autre appareil connecté.

La machine hôte garde le journal d’événements de la conversation, pour que tu puisses rejouer les réponses et l’activité des outils. Le travail continue tant que l’hôte n’est pas en veille et que Sillage tourne. L’accès distant de Desktop passe par ton réseau Tailscale privé.

Les messages en file sont conservés sur le serveur. L’envoi dans un tour en cours dépend de l’agent : le protocole actuel de Google Antigravity ne permet pas d’infléchir un tour en direct. Le guide des agents signale ces différences.

Un transfert transmet, dans la limite d’un budget, une sélection de messages complets et d’activité d’outils, ainsi que des références que l’agent suivant peut lire via Sillage. Le raisonnement, les pièces jointes et l’état natif des outils ne sont pas transférés.

Le menu Raccourcis explique chaque préfixe : fichiers (@), tickets (#), commandes (/) et skills ($ si l’agent les prend en charge).

Projets et planification

6 fonctionnalités

Garde reliés les tâches, les décisions et les sessions qui font le travail.

Une place pour chaque projetGarde ensemble les sessions, la configuration, le board, les fichiers et les worktrees d’un projet.

La navigation sépare les espaces de leur contenu. Sur Server, la configuration d’un projet a un seul propriétaire ; les membres peuvent travailler dans le projet et lire sa configuration. Desktop a un seul compte local. Sillage est pensé pour toi et des personnes de confiance, sur une même machine hôte.

Lien vers la fonctionnalité
Cartes locales et issues GitHubPlanifie sur un board qui réunit le travail local et les issues d’un dépôt lié.

Les cartes portent descriptions, commentaires, pièces jointes et sessions. Choisis si une nouvelle carte reste locale ou devient une issue GitHub ; les étiquettes et l’état des issues correspondent aux colonnes du board.

Lien vers la fonctionnalité
Relier le travail connexeLie les blocages, le travail connexe, les doublons, les tâches parentes, les sous-tâches et les remplacements.

Les relations apparaissent dans les deux sens et restent locales à Sillage. Les tags aident à organiser les cartes ; les agents peuvent en créer, sauf si le propriétaire du projet désactive cette option.

Lien vers la fonctionnalité
Garder la conversation avec sa tâcheRattache une session à une carte et retrouve cette carte dans la navigation, l’en-tête et le panneau de l’espace de travail.

Rattache-la depuis l’interface ou laisse un agent utiliser l’outil intégré. Les sessions d’un même projet peuvent modifier les cartes, laisser des commentaires, créer des tâches et fermer ou rouvrir les issues GitHub liées.

Lien vers la fonctionnalité
Sessions qui se coordonnentLaisse une session écrire à une autre ou attendre d’être prévenue quand elle a fini.

Si tu le demandes, un agent peut lancer une autre session Sillage avec son propre CLI, son modèle, son effort et son worktree. La nouvelle session reste visible comme les autres et démarre avec les permissions par défaut du projet.

Lien vers la fonctionnalité
Agir sur tes autres projetsLaisse les sessions d’un projet chercher, lire et lancer du travail dans les autres projets que tu possèdes ou partages.

Désactivé par défaut ; le propriétaire du projet l’active dans les réglages du projet. Les sessions peuvent alors chercher dans l’historique, lire et mettre à jour les cartes, lancer des actions et démarrer des sessions dans ces projets, tandis que la configuration de chaque projet reste la sienne. Un outil de journal de travail additionne le temps passé par jour et par projet. Réglage désactivé, un agent interrogé sur un autre projet te signale que ce réglage existe.

Contexte et outils

9 fonctionnalités

Consignes, mémoire et intégrations partagées entre tes agents.

Consignes de projet partagéesFixe une fois les conventions globales et celles du projet, et mets-les à la disposition des six agents.

Écris-les dans l’interface : Sillage les conserve, sans ajouter de fichier à ton dépôt. Ou garde les consignes d’un projet dans son propre AGENTS.md / CLAUDE.md, et Sillage n’ajoute que les consignes globales. Le délai avant qu’une modification atteigne une session en cours dépend du cycle de vie du contexte propre à chaque CLI.

Lien vers la fonctionnalité
Mémoire de projet d’une session à l’autreGarde dans une même mémoire de projet les décisions, les pièges et les faits que les agents apprennent.

La mémoire est partagée entre les worktrees du projet. Les agents peuvent lire et mettre à jour les notes avec les outils Sillage ; tu peux les corriger ou les supprimer dans l’interface du projet. Chaque CLI reçoit la mémoire par le mécanisme de contexte qu’il prend en charge.

Lien vers la fonctionnalité
Une bibliothèque de skills partagéeDécouvre, installe, mets à jour et gère les skills des agents qui s’en servent.

Garde des skills globaux ou propres à un projet, avec une progression visible pendant la recherche ou la mise à jour. Sillage distribue la bibliothèque à Claude Code, Codex, OpenCode, Grok Build, Google Antigravity et GitHub Copilot CLI selon leurs intégrations.

Lien vers la fonctionnalité
Serveurs MCP au même endroitDéclare une intégration une seule fois et choisis les agents et les projets qui la reçoivent.

Gère les serveurs globaux dans Réglages et ceux d’un projet sur la page du projet. Reconnecte un serveur qui était indisponible sans relancer la session ; Claude Code réessaie aussi les serveurs en échec au début d’un tour.

Lien vers la fonctionnalité
Intégrations proposées par les agentsUn agent peut suggérer un serveur MCP, puis te présenter un formulaire à vérifier.

Le serveur n’est ajouté que quand tu confirmes. Saisis toi-même les éventuels secrets : ces champs ne passent ni par le journal de la conversation ni par le modèle.

Lien vers la fonctionnalité
Choisir les outils des agentsActive ou désactive les familles d’outils de Sillage pour l’instance, puis pour chaque projet.

Les familles couvrent l’historique, le board, la coordination, la planification et les automatisations, les worktrees, les actions de projet, les consignes et la configuration du projet, plus des outils supplémentaires comme le navigateur. Un administrateur fixe les valeurs par défaut dans Réglages › Outils des agents ; le propriétaire d’un projet les remplace dans l’onglet Agents du projet. Une famille désactivée disparaît complètement de la session, ce qui raccourcit le contexte des CLI qui chargent la description de chaque outil. Les changements s’appliquent au prochain lancement du CLI d’une session.

Lien vers la fonctionnalité
Un navigateur pour les agents, suivi en directDonne aux agents un navigateur headless et suis la page depuis l’onglet Navigateur de la conversation.

Facultatif et désactivé par défaut. Les agents de tous les CLI reçoivent des outils de navigation qui pilotent un Chromium par conversation, isolé des autres. Prends la main pour te connecter ou passer une vérification, puis rends-la. Un navigateur que personne n’utilise se ferme au bout de dix minutes. Sillage réutilise le Chrome de la machine s’il en trouve un, et sinon télécharge Chromium à la première utilisation ; rien n’est embarqué dans les versions publiées.

Enregistre dans Sillage des comptes Claude, Codex, Grok Build, Google Antigravity et GitHub Copilot supplémentaires, et compare l’usage des abonnements quand l’intégration le permet. Les comptes ajoutés peuvent être choisis par l’utilisateur Sillage qui les a enregistrés. OpenCode, lui, utilise les fournisseurs configurés dans OpenCode.

Automatisation

8 fonctionnalités

Planifie une routine, réagis à un événement et fais remonter les décisions jusqu’à toi.

Tâches d’agent planifiéesLance un prompt à intervalle régulier, selon un motif cron ou à la date de ton choix.

Chaque exécution ouvre une session neuve avec le CLI, le modèle, l’effort et les permissions choisis, plus le contexte de l’exécution précédente. Les exécutions se rangent sous la tâche et ont une durée maximale. L’hôte ne doit pas être en veille, et Sillage doit tourner.

Lien vers la fonctionnalité
Vérifier d’abord, réveiller l’agent au besoinLaisse un petit script décider si une tâche planifiée a quelque chose à faire.

Une vérification réussie lance l’agent avec sa sortie. Un résultat « rien à faire » évite d’ouvrir une session : une surveillance récurrente ne consomme des tokens que s’il y a quelque chose à examiner. Un script proposé par un agent attend ta validation.

Lien vers la fonctionnalité
Travail déclenché par webhookServerDémarre une session quand un service envoie un événement, comme une issue étiquetée ou une CI en échec.

Inspecte le payload, construis conditions et prompts à partir de ses champs, et simule une livraison. Des modèles GitHub, des filtres facultatifs en bac à sable, la déduplication et des limites horaires aident à maîtriser les déclenchements entrants. Les automatisations déclenchées depuis Internet nécessitent une adresse publique pour Server.

Lien vers la fonctionnalité
Maintenance des issues GitHubDémarre si tu veux une session pour les nouvelles issues et transmets les commentaires ultérieurs au fil de l’issue concernée.

Choisis les consignes de maintenance, l’agent et le comportement vis-à-vis des worktrees. Le board lié garde ensemble l’issue et ses sessions Sillage.

Lien vers la fonctionnalité
Décisions pour les tâches autonomesPermets à un agent sans surveillance de te poser une question et de recevoir la réponse dans sa session.

Active les demandes de décision par tâche planifiée, webhook ou règle de maintenance GitHub. Une question peut avoir une échéance et un choix par défaut. Les décisions sont distinctes des demandes de permission du CLI.

Lien vers la fonctionnalité
Reprendre après une limite d’usageQuand une limite d’abonnement arrête un tour, vois quand elle se lève, ou laisse Sillage reprendre le tour tout seul.

Active la reprise automatique et fixe une attente maximale. Sillage reprend une fois par limite, sauf si quelqu’un a écrit ou interrompu entre-temps. Les exécutions planifiées sont signalées, sans reprise automatique.

Lien vers la fonctionnalité
Une API pour les tâchesCrée du travail, suis ses événements, réponds aux questions, infléchis ou interromps une session depuis tes propres outils.

L’API de tâches utilise des jetons Bearer à portée limitée, avec des restrictions de projet facultatives, distincts des sessions du navigateur. Reçois un webhook quand un travail se termine, ou crée des projets avec un jeton explicitement autorisé.

Lien vers la fonctionnalité
Brancher tes propres outils sur SillageDonne à un CLI externe l’accès à l’historique, aux boards, aux consignes et à la mémoire des projets via MCP.

Connecte-toi en stdio sur l’hôte ou via SSH, ou utilise le HTTP « streamable » avec un jeton d’API à portée limitée et des restrictions de projet facultatives. La messagerie entre sessions reste interne à Sillage.

Activité et analyses

7 fonctionnalités

Suis le travail en cours et comprends les résultats qu’il laisse derrière lui.

Un mur des sessions pour le travail en parallèleSuis plusieurs sessions côte à côte et fais passer devant celles qui ont besoin de toi.

La liste Activité pilote le mur : sélectionne ce qui attend, ce qui tourne ou ce qui n’est pas lu, ou ouvre une session précise. Enregistre des vues récurrentes avec des filtres ou une requête à la GitHub.

Lien vers la fonctionnalité
Ce qu’une session a coûté et utiliséSurvole une session dans la liste pour voir son coût équivalent API, ses appels d’outils, la taille de son contexte et sa carte liée.

Sur écran tactile, le bouton de détails ouvre le même résumé. Le coût est calculé comme sur la page Consommation, à partir des prix publics de l’API, et les appels d’outils en échec sont comptés à part.

Lien vers la fonctionnalité
Comprendre la consommation de tokensExplore l’usage des tokens par période, agent, modèle, projet, compte ou session.

Les graphiques quotidiens et mensuels incluent l’usage remonté des modèles auxiliaires et des sous-agents. L’équivalent en coût utilise les prix publics actuels de l’API, même pour le travail sous abonnement ; c’est une estimation, pas ta facture. Chaque compte Sillage voit toute l’instance.

Lien vers la fonctionnalité
Comparer les modèles sur le même travailLance un même prompt sur plusieurs agents, modèles et niveaux d’effort, avec des fichiers de départ et des vérifications facultatifs.

Chaque variante reçoit le même prompt, sans mémoire personnelle ni le prompt de plateforme de Sillage. Ordonne la composition, enregistre-la comme preset, et ajoute des variantes à un benchmark existant quand un nouveau modèle sort. Compare les mesures, les taux de réussite et les productions, évalue les runs à l’aveugle, trace le graphique d’une mesure et relance un benchmark au fil du temps. Les durées comptent le temps de travail : le chronomètre s’arrête quand un run t’attend.

Lien vers la fonctionnalité
Comparer les productions, pas seulement les chiffresExamine côte à côte des productions équivalentes, même quand les agents choisissent des noms de fichiers différents.

Exporte les mesures en CSV ou en JSON. Les totaux de tokens en entrée incluent, comme sous-ensembles, les lectures et écritures de cache remontées, ainsi que l’usage auxiliaire remonté. Les équivalents en coût suivent la même approche par prix publics que Consommation.

Lien vers la fonctionnalité
Faire un retour et commenter les runsEnvoie à un run terminé la correction que tu donnerais à l’agent, et écris ce que tu penses de chaque résultat.

Un retour poursuit la même session : ses chiffres s’ajoutent à ceux du premier essai, la vérification est relancée, et le run porte le texte que tu as envoyé, dans l’app comme sur les pages partagées et les diapositives. Éditions et accès

7 fonctionnalités

Choisis la façon dont Sillage tourne, avec les mêmes outils de projet essentiels.

Sillage DesktopDesktopUne app de bureau pour macOS Apple Silicon, Windows x64 et Linux x64 ou arm64.

Ouvre l’app et commence à travailler sans compte Sillage ni mot de passe. Son serveur intégré tourne avec l’app. Les agents se mettent en pause quand la machine se met en veille, et quitter l’app met fin aux sessions en cours. Desktop et Server gardent des données séparées. Choisis un téléchargement.

Lien vers la fonctionnalité
Sillage ServerServerFais tourner Sillage sur une machine que tu contrôles et ouvre-le dans ton navigateur.

Utilise une machine toujours disponible pour le travail au long cours et configure un accès privé ou HTTPS protégé pour tes appareils. Server prend en charge des comptes utilisateurs de confiance ; les agents et les terminaux partagent le compte système de l’hôte, ce n’est donc pas une isolation entre utilisateurs au niveau du système d’exploitation.

Accès privé depuis tes appareilsContinue sur un téléphone, une tablette ou un autre ordinateur grâce à une connexion à distance configurée.

Server peut passer par un VPN ou un proxy HTTPS protégé. Desktop propose un interrupteur Tailscale et un code QR dans Réglages ; seuls les appareils connectés au compte Tailscale du propriétaire de la machine sont acceptés. L’app de bureau doit rester ouverte.

Une app web installable, avec notifications pushServerInstalle l’interface de Server comme PWA et reçois une notification quand une session a besoin de toi.

Gère les appareils abonnés et envoie un test depuis Réglages. Les notifications restent silencieuses quand tu as déjà la conversation ouverte. Desktop prévient dans l’app, mais ne propose ni installation en PWA ni notifications push.
