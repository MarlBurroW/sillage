EN Installer Sillage

Six agents de code, chacun piloté par son propre CLI.

Sillage installe et lance les outils des éditeurs sur ta machine. Leurs modèles, leurs outils et leurs règles de compte restent les leurs ; les projets, le contexte et l’interface autour d’eux sont partagés.

Anthropic

Claude Code, avec ses plans, ses sous-agents et ses permissions.

Déroule un plan, suis les appels d’outils et les sous-agents, et relis les fichiers que Claude modifie. Tu gardes l’agent natif, avec tes projets et tes conversations rassemblés autour de lui.

Guide d’intégration de Claude Code

Comptes

Utilise la connexion du CLI, connecte un autre abonnement Claude ou ajoute une clé API Anthropic.

Pilotage

Choisis parmi les modèles, niveaux d’effort et modes de permission disponibles. Réponds dans la conversation aux questions et aux demandes de permission de Claude. Les sous-agents, les agents de workflow et les consultations du conseiller ont chacun leur propre fil ou leur propre ligne.

Contexte partagé

Sillage fournit les consignes partagées, la mémoire du projet, les skills et les outils MCP, à côté des capacités natives de Claude.

La disponibilité des modèles et les limites d’abonnement viennent de ton compte Claude. Quand, après une mise à jour du CLI, un alias comme haiku désigne un autre modèle, le fil te le signale.

OpenAI

Des threads Codex que tu peux reprendre.

Garde dans la même vue la conversation de développement, ses outils et la branche qu’elle modifie. Reprends un thread, choisis son modèle et son effort, et examine le résultat au fur et à mesure.

Guide d’intégration de Codex

Comptes

Connecte un abonnement ChatGPT par code d’appareil, ou configure une clé API. Choisis le compte de chaque conversation.

Pilotage

Les catalogues de modèles suivent le compte choisi. Les niveaux d’effort et les réglages de permission restent dans le composeur. Les résumés de raisonnement apparaissent dans le fil, et les sous-agents avec le modèle et l’effort qu’ils utilisent.

Contexte partagé

Utilise les consignes, la mémoire, les skills et les serveurs MCP de ton projet Sillage. Continue une conversation avec un autre agent quand l’étape suivante le demande.

L’accès aux modèles et les réglages pris en charge dépendent du CLI installé et du compte choisi.

Open source

OpenCode, avec les fournisseurs de modèles que tu as configurés.

Retrouve le choix de fournisseurs d’OpenCode dans le même espace de travail que tes autres agents. La conversation, les fichiers et les tâches restent ensemble, quel que soit le modèle qui répond.

Comment OpenCode reçoit le contexte partagé

Fournisseurs

Utilise les fournisseurs configurés dans OpenCode, modèles locaux compris quand le fournisseur les prend en charge.

Pilotage

Suis en direct les réponses et l’activité des outils, gère les permissions et garde les fichiers du projet à côté du fil.

Contexte partagé

Les consignes et l’index de la mémoire accompagnent chaque message. Les skills, les outils MCP et les transferts de conversation font le lien avec le reste de ton flux de travail.

Les modèles disponibles et la prise en charge des médias dépendent de la configuration de tes fournisseurs OpenCode.

xAI

Grok Build, l’agent de code de xAI.

Utilise l’agent de code natif de xAI depuis le même espace de travail. Suis ses modifications, réponds à ses questions et garde la conversation avec le travail dont elle fait partie.

Guide des comptes

Comptes

Utilise un abonnement Grok ou une clé API xAI, et choisis le compte de la conversation.

Pilotage

Suis les outils et les réponses dans la même vue de conversation, avec les options que propose l’agent natif.

Contexte partagé

Les consignes et la mémoire du projet entrent dans la session à sa création. Le même board, les mêmes worktrees, skills et outils MCP restent à portée de main.

Grok reçoit les consignes partagées à la création de la session ; une session existante garde le contexte avec lequel elle a démarré.

Google

Antigravity, l’agent maison de Google pour Gemini.

Lance Antigravity, l’agent officiel de Google, avec ses outils et ses permissions natifs. Choisis parmi ses modèles et ses niveaux de réflexion, sans changer ta façon de travailler sur tes projets Sillage.

Guide d’intégration d’Antigravity

Comptes et modèles

Utilise ce que propose Antigravity : choix du compte, commandes, import de l’historique et niveaux de réflexion propres à chaque modèle.

Contexte partagé

Partage les consignes du projet, la mémoire, les skills et les outils MCP. Transfère des conversations dans les deux sens avec les autres agents.

Limites

Un fork crée une nouvelle session avec un contexte portable. La compaction manuelle et l’infléchissement d’un tour en cours ne sont pas disponibles ; les messages peuvent attendre dans la file.

Le protocole n’expose ni fork natif, ni compaction manuelle, ni infléchissement d’un tour en cours, et Sillage le montre au lieu de le cacher.

GitHub

GitHub Copilot CLI, avec Auto et ses modes.

Lance l’agent de code de GitHub sur ton forfait Copilot. Laisse Auto choisir le modèle ou choisis-le toi-même, alterne entre Agent, Plan et Autopilot, et reprends les sessions que tu as lancées dans un terminal.

Guide d’intégration de GitHub Copilot

Comptes

Utilise la connexion Copilot de la machine, ou ajoute depuis Réglages des comptes connectés par code d’appareil. La jauge affiche les crédits IA ou les requêtes premium du forfait.

Pilotage

Choisis un modèle, ou Auto avec son profil de routage, ainsi qu’un mode et un niveau de permission. Avec Auto, un avis indique le modèle qui a répondu. Les questions et les demandes de permission arrivent dans la conversation.

Contexte partagé

Les consignes du projet, la mémoire, les skills et les serveurs MCP parviennent à Copilot. Transfère des conversations dans les deux sens avec les autres agents.

Copilot n’a pas de fork natif : un fork démarre une nouvelle session avec un contexte portable. Un message envoyé pendant un tour attend dans la file.

Ce qui ne change pas d’un agent à l’autre

Sillage fait tourner les agents natifs sur ta machine. Ce qui les entoure ne bouge pas.

La vue de conversation

Messages, activité des outils, questions et fichiers sont disposés de la même façon pour chaque agent.

Le contexte du projet

Les consignes partagées, la mémoire et les skills portent tes conventions de travail.

L’espace de travail

Le board, les worktrees Git, l’explorateur de fichiers et la revue de code restent à côté de la tâche.

Confier une conversation à un autre agent

Choisis un autre agent et un budget de contexte. Une nouvelle conversation s’ouvre avec l’historique retenu, dans le même worktree et sur la même carte de tâche. L’originale reste disponible, et la nouvelle y renvoie par un lien.

Guide du transfert de conversation

La demande d’origine

Ton premier message donne au prochain agent le point de départ du travail.

Les derniers échanges

Les messages récents gardent leur texte, leur ordre et leurs rôles, dans la limite du budget choisi.

L’activité d’outils pertinente

Les entrées et sorties récentes des outils accompagnent ces échanges, avec des limites de longueur.

Des références à l’historique plus ancien

Le prochain agent peut lire les échanges omis de la conversation d’origine quand il en a besoin.

Le raisonnement, les pièces jointes et l’état des outils natifs ne sont pas transmis. Tu écris la demande suivante dans la nouvelle conversation.

Installe les CLI depuis les réglages de Sillage et connecte-toi avec tes propres comptes.
