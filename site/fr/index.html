Ce qui tourne où.

Sillage tourne sur la machine de ton choix et y pilote les CLI officiels des agents. Tes projets et tes conversations restent sur cette machine, et les agents joignent leurs fournisseurs comme d’habitude.

  1. Tes écrans

    La fenêtre de Desktop, ou un navigateur sur ton ordinateur portable, ton téléphone ou ta tablette.

  2. Sillage

    Desktop sur ton ordinateur, ou Server sur une machine que tu contrôles. Projets, conversations, board et mémoire sont stockés dans sa base de données locale.

  3. Les CLI des agents

    Claude Code, Codex, OpenCode, Grok Build, Antigravity et Copilot CLI tournent sur la même machine, dans tes dépôts Git.

  4. Leurs fournisseurs

    Chaque CLI se connecte avec ton compte ou ta clé API et appelle son propre fournisseur. Sillage n’est pas un proxy et n’a aucun modèle à lui.

Ce qui reste sur ta machine, et ce qui en sort

Deux façons de le faire tourner.

Les deux ont les mêmes projets, agents, board et outils Git. Leurs données restent séparées, et tu peux utiliser l’un, l’autre ou les deux.

Desktop, sur ton ordinateur

Une app avec son propre serveur et son propre runtime Node. Rien à configurer ; elle se met à jour toute seule.

Prérequis, guides et accès distant

Avant d’installer.

Quelque chose manque ou reste flou ?

Ouvrir une issue
Sillage est-il gratuit ?

Oui. Sillage est gratuit et open source, sous licence MIT. Tu apportes les comptes, abonnements ou clés API que tes agents demandent. Il n’y a pas d’abonnement Sillage.

Sillage remplace-t-il mes agents de code ?

Non. Sillage fait tourner les outils natifs Claude Code, Codex, OpenCode, Grok Build, Google Antigravity et GitHub Copilot CLI. Ils gardent leurs propres capacités et leur propre gestion des permissions, et partagent une même interface pour tes projets et tes conversations.

De quoi ai-je besoin avant d’installer ?

Pour Desktop, l’app et Git : macOS le fournit avec les Command Line Tools d’Apple, Windows demande Git for Windows, et le .deb Linux l’installe. Pour Server, une machine Linux avec systemd ou un Mac Apple Silicon, avec curl, tar et Git ; le script d’installation apporte Node.js si besoin. Installe ensuite les CLI des agents depuis les réglages de Sillage et connecte-toi avec tes comptes.

Configuration requise
Où sont stockés mon code et mes conversations ?

Sillage stocke son espace de travail sur l’ordinateur ou le serveur que tu choisis. Tes agents parlent toujours aux fournisseurs d’IA configurés : héberger Sillage toi-même ne rend pas ces modèles locaux. OpenCode peut utiliser des modèles locaux quand ses fournisseurs les gèrent.

Sillage collecte-t-il des données sur moi ?

Non. Il n’y a ni télémétrie, ni statistiques d’usage, ni rapports de plantage, et rien sur toi ou ton code ne part chez son auteur. Sillage contacte bien quelques services de lui-même, comme GitHub pour vérifier les mises à jour ; la page sécurité les liste un par un, et précise quand.

Ce que Sillage envoie, et quand
Puis-je l’utiliser depuis mon téléphone ?

Oui. Ouvre Sillage Server dans le navigateur de ton téléphone, ou active l’accès distant dans Desktop, qui passe par Tailscale. Desktop doit rester ouvert ; Server tourne comme un service. Dans les deux cas, la machine hôte doit rester éveillée. Les notifications push sont disponibles dans l’édition Server.

Puis-je partager mon serveur avec une équipe ?

Server gère plusieurs comptes et des projets partagés pour des personnes de confiance. Les agents tournent sous le même compte système : ce n’est donc pas un environnement isolé pour des utilisateurs en qui tu n’as pas confiance. Place-le derrière un VPN ou une adresse HTTPS protégée. Guide d’accès à distance

Comment fonctionnent les mises à jour ?

Desktop cherche une nouvelle version sur GitHub au démarrage puis toutes les quatre heures, la télécharge en arrière-plan et l’installe quand tu choisis Redémarrer et mettre à jour. Server se met à jour depuis Réglages › À propos ou en relançant la commande d’installation, et garde les deux versions précédentes sur le disque. Avec Docker, récupère une image plus récente.

Sillage est-il mature ?

Jeune, et il évolue vite : 53 versions depuis juillet 2026, chacune listée avec ses notes. Une bonne partie de Sillage est construite depuis Sillage lui-même, donc ses parcours de tous les jours sont utilisés en permanence. Les bugs et les imperfections vont dans les issues GitHub.

Pourquoi Sillage existe

« Je voulais un seul endroit, sur un serveur à moi, où reprendre un projet depuis mon téléphone, sans transporter d’ordinateur portable ni garder le fil d’une douzaine de terminaux. »
MarlBurroWCréateur de Sillage

Je voulais aussi garder les agents que j’utilisais déjà. Sillage fait tourner leurs outils natifs et leur donne un espace de travail commun : projets, board, consignes et mémoire. Une session peut retrouver une décision antérieure et laisser du contexte à l’agent suivant, même quand je change de CLI.

Claude Code et Codex ont écrit l’essentiel de Sillage, en grande partie depuis Sillage lui-même, souvent depuis un téléphone.
