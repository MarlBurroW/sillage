Sillage 0.14.0 vise Claude Code 2.1.291 et garde Ultracode actif quand tu changes l’effort.

## Nouveautés

- **Claude Code 2.1.291.** La version préférée de Claude Code passe de 2.1.273 à 2.1.291, et l’Agent SDK à 0.3.291. Les réglages signalent un CLI plus ancien et proposent d’installer celui-ci. Opus 5.5 et Sonnet 5.5 apparaissent d’eux-mêmes dans la liste des modèles, puisque cette liste est lue depuis le CLI.
- **Ultracode n’est plus un niveau d’effort.** Depuis Claude Code 2.1.284, Ultracode est un interrupteur à part et tient à n’importe quel effort. L’activer dans Sillage laisse désormais l’effort où il est. Changer l’effort d’une conversation en Ultracode ne le coupe plus dans le dos du composer : le CLI abandonne Ultracode quand l’effort change sans lui, et Sillage envoie désormais les deux. Ultracode reste proposé uniquement sur les modèles qui ont un niveau d’effort très élevé, ce que le CLI exige.

## Correctifs

- **Les conversations sur un modèle renommé par le CLI gardent leurs réglages.** Claude Code a retiré `opus[1m]` de sa liste (Opus a désormais un contexte de 1M par défaut) et liste Fable 5.1 sous `fable`. Les conversations enregistrées sous les anciens noms affichaient un identifiant brut et perdaient leurs réglages d’effort, de vitesse et d’Ultracode. Elles retrouvent désormais le modèle qu’elles désignent.
- **Les plugins que Claude Code n’a pas pu charger sont signalés** dans la conversation, une fois, au lieu que leurs skills disparaissent sans un mot. Sillage charge sa bibliothèque de skills sous forme de plugins.
- **Un contexte effacé dit pourquoi** : `/clear`, ou un plan approuvé sur un contexte effacé.

## Déploiement

- Le modèle de service Linux plafonne désormais la mémoire à 75 % de la RAM (`MemoryHigh=75%`) au lieu de 2G. Les agents et les serveurs de développement qu’ils lancent comptent dans ce plafond, et à 2G le noyau pouvait ralentir le service jusqu’à figer le daemon. **Les installations Linux existantes gardent leur valeur actuelle** : la mise à jour intégrée ne réécrit pas l’unité. Relance `install.sh`, ou fixe ta propre valeur avec `systemctl --user edit sillage`.

## Limite connue

Claude Code arrête une commande que Claude lance en arrière-plan une fois son délai expiré : 30 minutes par défaut, 2 heures au plus. Depuis 2.1.288, cela ne s’applique qu’aux sessions qu’il considère comme sans surveillance, ce qui inclut toutes les sessions qu’un hôte SDK comme Sillage démarre. Un serveur de développement que Claude lance en arrière-plan s’arrête donc au bout de 30 minutes, sauf si Claude demande plus longtemps. Cette version n’y change rien.
