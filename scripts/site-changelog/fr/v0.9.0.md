Sillage 0.9.0 tourne sous Windows via WSL2, et permet aux sessions d’un projet de se coordonner entre elles.

## Nouveautés

- **Windows via WSL2.** L’installateur en une ligne fonctionne désormais dans WSL2. Il active systemd quand la distribution ne l’a pas, et ajoute une entrée **Sillage** au menu Démarrer, et en option à l’ouverture de session Windows, qui garde WSL en marche une fois le terminal fermé et ouvre Sillage dans le navigateur de Windows. Voir le [guide WSL2](https://github.com/MarlBurroW/sillage/blob/main/docs/windows.md).
- **Plus de prérequis Node.js.** Sans Node 22+ dans le PATH, l’installateur télécharge la version LTS actuelle de Node (somme de contrôle vérifiée) sous `~/.local/share/sillage/node`, pour le seul service. Le script est aussi lu en entier avant de s’exécuter : un téléchargement tronqué, ou une commande qui lit stdin, ne peut plus exécuter un demi-installateur.
- **Des sessions qui se parlent.** Le serveur MCP intégré gagne `send_session_message`, `read_session_messages`, `notify_when_done` et `broadcast_session_message`, et `list_sessions` indique la branche et les fichiers modifiés de chaque arbre. Le daemon relaie les messages, la conversation les montre comme venant d’une session, et un échange est mis en attente après six allers-retours pour que deux agents ne puissent pas tourner en boucle.
- **Des reprises Codex plus légères.** Reprendre ou forker un fil Codex ne rapatrie plus tout son historique (48 Mo pour un seul fil), ce qui pouvait mettre le daemon à court de mémoire.
- **Liens dans l’aperçu Markdown.** Les liens relatifs et les images de l’aperçu de l’éditeur se résolvent depuis le dossier du document, comme sur GitHub, et sont cliquables depuis un panneau de projet.

## Mise à jour

Les installations faites avec l’installateur se mettent à jour depuis Réglages › À propos, ou en relançant la commande d’installation. Une migration de base de données (messages entre sessions) s’applique au démarrage.

## Distribution

Les archives Linux x64 et arm64 sont jointes. L’image Docker multi-architecture est disponible sous `ghcr.io/marlburrow/sillage:0.9.0`. Le chart Helm de `main` utilise cette version par défaut ; depuis le tag `v0.9.0`, passe `--set image.tag=0.9.0`.

## Validation

Typage, lint, build, vérification des bindings Codex et 47 tests serveur réussis, et migrations appliquées à une base vide. L’installateur WSL2 a été éprouvé de bout en bout dans une machine virtuelle Windows 11 (WSL 3.0.1, Ubuntu 26.04 et 24.04) : installation neuve et relance, systemd désactivé, fermeture du terminal, redémarrage de Windows, installation de Codex depuis l’interface, et désinstallation.
