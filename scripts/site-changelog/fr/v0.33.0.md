## Nouveautés

### Benchmarks
- Une nouvelle section **Benchmarks**, sous Discussions, exécute un même prompt sur plusieurs modèles, niveaux d’effort et CLI. Les runs démarrent sans mémoire personnelle ni prompt de plateforme, si bien que chaque variante reçoit le même texte.
- Chaque run indique la durée, les tokens, le coût, les appels d’outils et plus encore. Les valeurs qu’un CLI ne fournit jamais restent vides au lieu de passer en tête du classement.
- Ajouter des fichiers de départ et un script de vérification, puis comparer côte à côte les réponses et les fichiers produits, pages rendues comprises.
- Évaluer les runs à l’aveugle, tracer une mesure d’une variante à l’autre, exporter en CSV ou en JSON, et relancer un benchmark pour le suivre au fil des versions des CLI.

### Serveurs MCP
- Les agents peuvent proposer un serveur MCP avec `install_mcp_server`. Rien n’est écrit tant que tu n’as pas confirmé le formulaire dans la conversation, et les secrets que tu saisis n’atteignent jamais le journal ni le modèle.
- Les serveurs peuvent désormais appartenir à un projet : ils atteignent toutes les conversations de ce projet et aucune autre, et disparaissent avec lui. Deux projets peuvent avoir chacun leur propre `postgres`.
- Les serveurs d’un projet se gèrent depuis une nouvelle section MCP sur sa page ; les serveurs globaux restent dans les réglages.

### Une règle pour savoir qui modifie quoi
- La configuration globale appartient aux administrateurs, celle d’un projet à son propriétaire, et les membres d’un projet partagé la lisent sans la modifier. La même règle couvre désormais les consignes, la mémoire, les skills et les serveurs MCP, dans l’interface comme dans les outils des agents.

### Agents et délégation
- Un agent peut lancer autant de sessions qu’un travail le demande : la limite de six lancements par heure disparaît. La limite de deux niveaux de chaînes de lancement reste.

### Interface
- Un sélecteur de projets avec recherche, qui montre les logos des projets, sert désormais à la portée MCP, aux permissions d’API, aux destinations des skills et aux filtres des services.
- Les avertissements répétés des agents sont regroupés en encarts compacts, dont le texte complet reste accessible. Les erreurs restent aussi visibles qu’avant.
- Les liens `file://` écrits par les agents ne s’affichent plus en Markdown brut : un fichier de l’espace de travail s’ouvre dans l’éditeur, tout le reste s’affiche en texte simple.

## Notes de mise à jour
- Trois migrations de base de données (0060 à 0062) s’exécutent au premier démarrage : tables des benchmarks, portée projet des serveurs MCP, et suppression de l’index unique, à l’échelle de l’instance, sur les noms des serveurs MCP.
- Les propriétaires de projet qui ne sont pas administrateurs peuvent désormais gérer les serveurs MCP de leur projet, et un agent dans un projet partagé ne peut plus réécrire les consignes ou l’image du projet pour le compte d’un membre qui n’en est pas propriétaire.
- La limite horaire de lancements couvrait aussi l’API et les clients MCP externes : ils ne sont donc plus plafonnés non plus. Restreins tes jetons d’API si tu comptais dessus. Les limites des automatisations et du board GitHub ne changent pas.
