GitHub Copilot CLI arrive comme sixième agent, tu peux choisir les polices de l’interface et du code, et la réflexion se lit désormais à part des appels d’outils, Codex montrant enfin la sienne.

**GitHub Copilot CLI**
- Copilot CLI (1.0.116, par ACP) se choisit comme les autres agents : modèles lus auprès de Copilot lui-même avec Auto en tête, son profil de routage (efficacité, équilibre, intelligence) proposé quand le modèle est Auto, appels d’outils et modifications affichés comme pour les autres CLI, et une jauge de quota qui suit le budget mensuel du forfait.
- Pas encore là : les comptes Copilot supplémentaires dans les réglages, et une page sur le site.

**Apparence**
- Réglages › Apparence › Polices permet à chaque compte de choisir une police pour l’interface et une pour le code parmi les Google Fonts. Les polices sont livrées avec Sillage : aucune requête ne quitte l’instance et Desktop fonctionne hors ligne ; une famille ne se télécharge qu’une fois choisie. Le terminal suit la police du code.

**Conversations**
- La réflexion se lit en prose italique derrière un filet fin, au lieu d’un encadré qui ressemblait à un appel d’outil. Elle se déplie pendant qu’elle s’écrit et se replie dès que la réponse commence.
- Les sessions Codex montrent désormais leurs résumés de réflexion : Sillage ne les demandait pas, si bien que Codex n’affichait jamais la moindre réflexion.
- Les appels au navigateur des agents portent le logo Sillage et des libellés lisibles, au lieu d’un nom brut d’outil MCP.
- Les lignes d’outil montrent le niveau d’effort d’un sous-agent, et signalent quand Read prend un gros fichier en entier.
- Les détails de session donnent la version de Claude Code que la session fait réellement tourner, qui peut différer de celle installée après une mise à jour, et indiquent si le compte a de l’usage supplémentaire ou s’arrête à la limite.

**Aperçus des serveurs de dev**
- Les agents peuvent donner un titre à la carte de chaque serveur qu’ils lancent, la faire pointer vers une page précise, ou la garder hors du fil (elle reste dans l’onglet Aperçu) : une API, un worker et une app web ne partagent plus une même carte générique.
- Un serveur qui s’arrête laisse une ligne dans le fil au lieu de disparaître. La carte peut copier l’adresse et créer un lien de démo.

**Réglages**
- Une nouvelle page Réglages › Notes de version liste les versions récentes, en marquant celle qui est installée et celles qui ne le sont pas encore. À propos y renvoie.

**Correctifs**
- Un message qui n’a jamais atteint son CLI, ou un CLI mort au lancement, ne laisse plus la conversation réfléchir indéfiniment ; « Interrompre l’agent » clôt désormais un tel tour. Un dossier de travail manquant est nommé au lieu d’être signalé comme un binaire cassé.
- Créer un projet dans le dossier d’un projet existant (le piège `project/project`) déclenche désormais un avertissement et propose plutôt d’ajouter le dossier parent.
- Les tâches planifiées, les automatisations et les tâches de l’API qui utilisent Claude attendent la fin des surcharges de l’API (jusqu’à 30 minutes) au lieu d’échouer après quelques tentatives. Les conversations interactives échouent toujours vite.
- Après une reprise, Codex exécute chaque tour dans le mode qu’affiche le composer, Plan ou Default.
- `remove_worktree` ne refuse plus un worktree qu’un agent vient de fusionner dans son shell.
- Les projets archivés n’acceptent plus les demandes d’autres sessions, et le plafond de 20 tâches ne compte que les tâches créées par des agents : tes propres planifications ne peuvent plus bloquer les agents.
- Antigravity ne laisse plus de dossier `skills/system` non suivi dans les projets.
- Un message en file envoyé pour infléchir le tour n’est plus perdu si le chargement de la conversation échoue. OpenCode réessaie quand son port est déjà pris au démarrage.

**Agents**
- Versions ciblées : Claude Code 2.1.332 (SDK 0.3.332) et Codex 0.172.0. Avec un Claude Code assez récent, les serveurs MCP passent par la requête initialize plutôt que par la ligne de commande, où leurs secrets étaient visibles de tous les utilisateurs de la machine via `ps`.

**Sous le capot**
- Le gestionnaire de sessions, la page de conversation et l’explorateur de fichiers sont découpés en modules plus petits, l’app web reçoit un harnais de tests unitaires, et les sections des réglages se chargent à la demande, ce qui laisse de la marge sous la limite de précache de la PWA.

Éditions Server et Desktop. Deux migrations de base de données (0078, 0079), appliquées automatiquement au démarrage.
