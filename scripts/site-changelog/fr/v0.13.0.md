Sillage 0.13.0 s’installe nativement sur macOS avec Apple Silicon, avec le même script en une ligne que sous Linux.

## Nouveautés

- **macOS (Apple Silicon).** Lance `curl -fsSL https://raw.githubusercontent.com/MarlBurroW/sillage/main/install.sh | bash` depuis Terminal. L’installateur récupère Node si le Mac n’en a pas de suffisamment récent, met en place un agent launchd qui démarre avec ta session et continue de tourner une fois Terminal fermé, crée le premier compte et ouvre Sillage dans le navigateur. Les mises à jour passent ensuite par Réglages › À propos, comme sous Linux. Il faut git : lance d’abord `xcode-select --install` si les Command Line Tools manquent. Les logs vont dans `~/.local/share/sillage/logs/sillage.log`. Les Mac Intel ne sont pas pris en charge.
- **Les terminaux se comportent comme dans Terminal.** Sur macOS, Sillage ouvre des shells de connexion : `~/.zprofile` s’exécute et Homebrew est dans le PATH. Le délai d’inactivité épargne toujours un shell qui fait tourner un serveur de développement.

## Correctifs

- **Les identifiants git de Sillage passent en premier.** Un dépôt cloné par Sillage efface désormais les credential helpers hérités de la configuration git système et globale avant d’ajouter le sien. Jusqu’ici, un tel helper répondait en premier : `osxkeychain`, configuré par git sur chaque Mac, fournissait tes propres identifiants puis gardait le jeton de Sillage dans le trousseau. Il en allait de même pour un helper global sous Linux. Cela s’applique aux dépôts clonés à partir de maintenant.
- **Node 22 avant 22.14 est écarté.** better-sqlite3 a besoin de N-API 10, arrivé avec Node 22.14. Un Node plus ancien le chargeait sans un mot, puis plantait à la première requête. L’installateur n’utilise désormais le Node du système qu’à partir de 22.14, et installe le sien sinon. La vérification du module natif, dans l’installateur et dans la mise à jour intégrée, exécute une requête au lieu d’un simple `require`.
- **Le premier compte est demandé dès qu’il n’en existe aucun.** L’installateur ne le demandait que lorsque la base n’existait pas encore. Une exécution qui échouait après le démarrage du service laissait une base vide, et l’exécution suivante ne demandait rien.
- **Une release sans archive pour ta plateforme le dit** au lieu de signaler un téléchargement échoué.

## Déploiement

- Les releases incluent désormais l’archive `sillage-vX.Y.Z-darwin-arm64.tar.gz`, construite et installée de bout en bout sur Apple Silicon par la CI.
- `SILLAGE_ARCHIVE=path/to/sillage-*.tar.gz` installe une archive déjà présente sur le disque.
- Le Node minimal est désormais 22.14, pour l’installateur comme pour le développement.

## Hors de cette version

Sur macOS, la vue des processus (Services) reste réservée à Linux, et le fichier de log n’est pas soumis à rotation. Le credential helper d’un dépôt cloné pointe toujours dans le dossier de la release avec laquelle il a été cloné, qui disparaît après trois mises à jour.
