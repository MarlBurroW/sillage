Les sessions arrêtées par la limite d’usage d’un abonnement peuvent désormais reprendre d’elles-mêmes, et le sélecteur de modèles Claude garde sa liste complète.

- **Reprise après une limite d’usage** (#23). Quand Claude Code ou Codex arrête un tour sur la limite de ton abonnement, Sillage te prévient une fois, avec l’heure de levée de la limite : notification push, toast dans l’app et ligne visible dans le fil. Active la reprise automatique dans **Réglages › Limites d’usage** et la session reçoit un message de reprise (texte de ton choix) une fois la limite levée. Une session reprend une fois par limite, jamais si tu l’as interrompue, si tu y as écrit ou si tu l’as archivée entre-temps, et pas si la limite se lève plus tard que ton seuil (12 heures par défaut). Les exécutions planifiées sont seulement signalées : la suivante repart de zéro. La reprise en attente est enregistrée sur le serveur, elle survit donc à un redémarrage du daemon. Désactivée par défaut : le travail repris consomme ton quota.
- **Liste complète des modèles Claude.** Avec Claude Code 2.1.318, le CLI peut répondre avec sa liste compilée au lieu du catalogue servi par Anthropic ; le sélecteur ne retombe plus sur la courte liste de cinq alias (Défaut : Opus / Opus / Fable / Sonnet / Haiku). Le bouton de rafraîchissement prend toujours la réponse du CLI. Une session laissée sur « Défaut » démarre désormais sur le modèle annoncé par le sélecteur (par exemple Fable 5.1) au lieu de celui que le CLI choisit pour ce processus.

Base de données : une migration additive (`usage_limit_resumes`). Édition Desktop : pas de push, donc l’arrêt sur limite s’affiche en toast et dans le fil.
