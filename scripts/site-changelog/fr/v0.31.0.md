## Nouveautés

### Exporter et partager une conversation
- **Exporter et partager**, dans la barre d’outils de la conversation, transforme une session en page HTML autonome : titre, introduction et pseudonyme facultatif modifiables, extrait entre deux messages, et messages retirés un à un.
- L’activité des outils est résumée par défaut, sans arguments, résultats ni chemins. Masque-la, ou inclus les entrées et sorties appel par appel.
- Les secrets, adresses e-mail, adresses IP et chemins personnels sont détectés localement et masqués par défaut. Passe en revue chaque détection, masque à la main des mots ou des sélections, et vérifie chaque image que tu choisis d’inclure.
- L’aperçu, le téléchargement HTML et la page publiée sont le même fichier. Il fonctionne hors ligne et n’exécute aucun JavaScript.
- Sillage Server, avec une URL publique, peut publier la page sous forme de lien anonyme qui expire par défaut au bout de 30 jours et se révoque depuis **Liens partagés**. Sillage Desktop propose le téléchargement HTML.

### Des worktrees pour les sessions longues et autonomes
- **Tout nettoyer**, dans la vue Chantiers, supprime en une seule confirmation tous les arbres fusionnés ou introuvables. Décoche les arbres à garder ; les arbres où une session travaille sont laissés de côté, et chaque arbre est réévalué sur le serveur avant sa suppression.
- Nouvel outil MCP `remove_worktree` : les agents suppriment les arbres qu’ils ont créés une fois le travail fusionné. Un travail non fusionné est refusé sauf en forçant, et un agent ne peut pas supprimer son propre arbre. Seules les sessions qui ont vécu dans l’arbre sont archivées.
- Un worktree Sillage supprimé avec un simple `git worktree remove` est désormais oublié au lieu de rester affiché pour toujours comme introuvable.
- Une session qui a écrit dans plusieurs worktrees porte, dans la barre latérale, l’étiquette du dernier qu’elle a touché plutôt que celle du plus alarmant.

### Des serveurs MCP qui reviennent
- Un serveur MCP en échec se reconnecte depuis le panneau MCP sans redémarrer la session. Claude Code retente aussi les serveurs en échec au début de chaque tour, si bien qu’un backend démarré après la session est pris en compte tout seul. OpenCode gère la reconnexion serveur par serveur ; Codex, Grok Build et Antigravity indiquent qu’ils ne le peuvent pas.

## Notes de mise à jour
- Une migration de base de données (0059, partages de conversation) s’exécute automatiquement au premier démarrage.
- Le partage public demande que l’URL publique soit définie dans les Réglages de Sillage Server. Les fichiers exportés sont stockés dans le dossier de données, sous `conversation-exports/`.
- Server et Desktop se comportent de la même façon pour tous les autres changements de cette version.
