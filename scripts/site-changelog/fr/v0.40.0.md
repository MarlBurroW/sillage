La prise en charge d’OpenCode 2, des agents de workflow lisibles, et une vue plus claire de ce que font les sous-agents.

**OpenCode 2**
- Sillage installe désormais OpenCode 2 (`@opencode/cli` 2.4.1) comme OpenCode géré, et fonctionne toujours avec la 1.x. La version est détectée au démarrage d’une conversation.
- Les sous-agents et les shells en arrière-plan se suivent et s’arrêtent depuis le panneau Agents, avec la sortie des shells en direct. Les skills de la bibliothèque et les sessions lancées hors de Sillage sont aussi pris en charge.
- Le premier démarrage d’OpenCode 2 migre sur place sa base locale de sessions. La page Versions des CLI l’explique avant la mise à jour.

**Sous-agents et workflows**
- Les agents des workflows (Claude Code) s’ouvrent désormais depuis le panneau Agents. Leurs fils sont lus dans les transcripts qu’écrit Claude Code et se mettent à jour à quelques secondes d’intervalle pendant qu’ils tournent. Les workflows terminés restent accessibles depuis leur carte.
- Le fil d’un sous-agent se termine désormais par le même indicateur d’activité qu’une conversation, et affiche une courte ligne d’état que Claude écrit sur chaque sous-agent en cours.
- Un sous-agent lancé en arrière-plan peut être arrêté seul, depuis son fil.
- Quand un sous-agent laisse une commande tourner en arrière-plan, sa fin apparaît désormais dans le fil de ce sous-agent plutôt que dans le fil principal.
- Les tuiles d’Activité montrent la fin du fil principal même quand un sous-agent est occupé. Avant, une tuile pouvait ne montrer qu’une seule carte.

**Contexte des sessions**
- La liste des sessions voisines, ainsi que les rappels de titre, de carte et d’image, partent désormais avec le premier message de chaque lancement plutôt que dans le prompt système. Claude garde le premier prompt système à la reprise d’une session, si bien que cette liste restait figée. OpenCode ne perd plus son cache de prompt à chaque tour.

Disponible dans les éditions Server et Desktop. Aucune migration de base de données. Les workflows lancés avant cette version n’enregistrent pas les identifiants de leurs agents : leurs fils ne peuvent pas être ouverts.
