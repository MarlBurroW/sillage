Sillage now connects work to GitHub and to external events, lets autonomous sessions ask for a decision, and lets you choose the Claude or Codex account for each conversation.

## GitHub, automations and decisions

- Link the board to GitHub issues: local cards and issues side by side, synced comments, columns tied to the issue's labels and state. Choose whether new cards stay local or become issues.
- Turn on maintenance for a new issue or comment, with its own instructions, CLI, model and permissions. One session per issue receives the following comments, in a dedicated worktree or at the project root.
- Trigger sessions by webhook: GitHub templates for a labeled issue, a command in a comment, an opened PR or a failing CI; conditions and prompts built from the payload; an optional sandboxed JavaScript filter. A simulator and a call log let you check the rules without starting an agent. Deduplication and hourly limits keep launches in check.
- Run a script before a scheduled task: exit 0 wakes the agent with the result, exit 10 skips the run without opening a session. A script proposed by an agent waits for an approval that shows in the conversation.
- Allow autonomous sessions to ask a question in **To decide**, with a deadline and an optional default choice. The answer goes back to the session. This option is off by default for each source and stays separate from the CLI's native permissions.
- Receive questions and decisions as a toast in the app and as a push notification on other devices, without being notified about a conversation already on screen. Manage devices and test notifications from the settings.

## Accounts and workspace

- Add several Claude and Codex subscriptions or API keys from Sillage, with a guided sign-in. Choose the account when creating the conversation or in its composer; additional accounts belong to the Sillage user who added them.
- Compare subscription usage before choosing. Additional Claude subscriptions offer a second guided sign-in to enable their gauge; API keys have no subscription gauge.
- Pin the settings you want under the composer, with a layout specific to each CLI: permissions, account, speed, advisor and the other available controls.
- Save project actions: tests, a dev server or a script to run from the header, the panel or the palette. Tasks keep their output and exit code; services use systemd on Linux, with a terminal fallback elsewhere. Commands proposed by agents are reviewed before their first run from the interface.
- Organize project navigation into Board, Sessions and Automations sections.

## API and MCP

- Create projects with `POST /api/v1/projects`, the `projects:write` scope and a token with no project restriction.
- Connect an external CLI to Sillage's MCP server in global mode: browse projects, read history, board, instructions and memory, then start work on behalf of an account.
- Reach the MCP server remotely over Streamable HTTP at `/api/v1/mcp`, with a token carrying the `mcp` scope and, if needed, a list of allowed projects. The stdio mode, local or over SSH, remains available. Messages between sessions remain reserved for Sillage sessions.

## Versions and upgrade

Targeted CLI versions: **Claude Code 2.1.296** (SDK 0.3.296), **Codex 0.162.1**, **OpenCode 1.19.0**. The OpenCode adapter targets the 1.x line.

This release applies nine migrations since v0.17.0 (`0033` to `0041`) for actions, automations, scheduled checks, the GitHub board, decisions, accounts and out-of-session MCP requests. The migrations apply at startup; keep a backup of your data before updating.

Validation: type checking, lint, 235 server tests, a full build, Codex and OpenCode bindings; website checked with Playwright in light and dark at 320, 390, 768 and 1440 pixels, with and without JavaScript.

Linux/macOS CI and the macOS installation passed. The Linux x64 archive was started on a disposable database: version 0.18.0, home page, JavaScript assets, SPA fallback and MCP authentication checked. Helm chart validated by lint and manifest rendering.
