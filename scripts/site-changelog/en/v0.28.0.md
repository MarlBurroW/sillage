CLI updates can be managed from the settings, and a Codex session no longer fails to start when the user's configuration already has an MCP server named `sillage`.

## What's new

- **CLI updates in the settings**: see the installed and recommended versions, then install or update the agents Sillage manages. The replacement waits for active sessions to finish, then refreshes the available models.

## Fixes

- **Codex and MCP**: a user configuration that already contains an HTTP server named `sillage` no longer blocks a session from starting. The built-in server now uses `sillage_builtin`. Configuration errors name the server concerned instead of showing an internal error, including when a session resumes.
- **Desktop on Windows**: visible update progress, and an explicit message when a package is not available yet.

The MCP fix applies to Sillage Server and Desktop. Older histories remain readable and user configurations are kept.

Desktop packages for Windows, macOS and Linux are available. The update is offered in **Settings › About**.
