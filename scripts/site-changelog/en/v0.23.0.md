Any session can now edit its project's tickets and link them to each other, a conversation shows its worktree and can clean it up, and Git lists with thousands of files stay usable.

## Editable tickets and ticket relations

- Any session can edit the title and description of any ticket in its project and add notes to it, without having to be attached to it.
- New **Relations** section: blocks / is blocked by, is related to, duplicate, parent / sub-ticket and replacement. Search by number or title, go to the linked ticket, and remove a relation from either side.
- Agents get `update_card`, `link_cards` and `unlink_cards`; `read_card` shows the relations. Links are informational and stay local to Sillage, even for GitHub issues. `#n` mentions remain plain references.
- Links to the ticket itself and cycles are refused; a sub-ticket has a single parent.

## Worktrees and decisions

- **To decide** focuses on the decisions requested by autonomous agents. Automatic worktree cleanup proposals are gone.
- The branch, the worktree's state and its cleanup, with confirmation, are available directly in the conversation.

## Git fixes

- Lists of several thousand files stay usable thanks to search and pagination; bulk actions also cover files outside the displayed page.
- Paths resolve correctly from a subfolder of the repository, and diff errors are shown.

## Installation and validation

Available for **Sillage Server and Sillage Desktop**. An additive migration for ticket relations is applied automatically at startup.

Validation: 343 tests, type checking, lint and build passed; the relations flow was checked on Server and Desktop, on a large screen and at phone size.
