Sillage Desktop comes to Windows and downloads in one click from the website, and every new installation opens on a tour that sets Sillage up for real.

## Sillage Desktop on Windows

- Install Sillage on Windows (x64) with a per-user installer, without administrator rights. The app bundles the server and its Node, as on macOS and Linux.
- Terminals open in PowerShell (PowerShell 7 if it is installed). Project actions and check scripts, written in `sh` syntax, run through the bash of Git for Windows, which is now required.
- Run the four CLIs on Windows, including those the app installs with its bundled npm. Sillage reads npm's `.cmd` launchers to start their real target: a native binary (Claude Code, OpenCode) or a Node script (Codex, Grok).
- Handle the other Windows particularities too: `C:\` paths and drives in the folder picker, junctions instead of symbolic links, a clean server shutdown, no console window. Data goes to `%LOCALAPPDATA%\Sillage`.
- The app is not signed yet: SmartScreen asks you to confirm the first launch ("More info", then "Run anyway").

## Direct download

- Packages have stable names (`Sillage-win-x64.exe`, `Sillage-mac-arm64.dmg`, `Sillage-linux-amd64.deb`…), which `releases/latest/download/` always serves in their latest version.
- The website offers the package for the visitor's system and lists all the others; the README and the guide give the same direct links.

## First-run tour

- On first sign-in, a step-by-step tour explains each idea in Sillage by setting it: profile, appearance, agents (detected CLIs, installation, additional accounts), how each CLI works, instructions and memory, then a summary. It can be replayed from Settings › About.
- On a hosted instance, the first account is created from the browser when the database has none, so the terminal is no longer needed. The public address becomes an instance setting, read by webhooks, the API and scheduled tasks.
- In the desktop app, the tour is shorter: no account, no address, no phone.
- Choose where the instructions and memory of new projects live, and, if needed, leave a project's memory to each CLI.
- Sample projects written by Sillage become a workspace origin on the New project screen.

## Grok accounts

- Add additional Grok accounts, as for Claude and Codex: sign-in with a device code or an xAI key, a usage gauge per account, and account choice in the composer.

## Versions and upgrade

Targeted CLI versions unchanged: **Claude Code 2.1.301** (SDK 0.3.301), **Codex 0.163.0**, **OpenCode 1.19.3**, **Grok Build 1.0.62**.

Two additive migrations since v0.20.0, applied at startup: `0045_grok_accounts` (Grok accounts table) and `0046_memory_mode` (`projects.memory_mode` column, default `sillage`). Keep a backup of your data before updating.
