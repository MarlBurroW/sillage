Agents can now move board cards, cards cited in replies open in one click, and installing a CLI from the interface finally shows what it is doing.

## Board

- Agents move cards with the new `move_card` tool, when asked or to move their own card to "To review" when the work is ready for review; "Done" and "Abandoned" remain the user's call unless they ask. Each move leaves a line in the card's activity.
- A card in progress or to review moves to "Done" when its worktree is merged into the base branch, once all its sessions are idle. A card moved back by hand is not moved forward again. On a board linked to GitHub, the issue then closes.
- `#12` references in replies, descriptions and notes become links to the card, with a preview on hover (column, title, start of the description). Only cards that exist in the project are linked.
- Sort each column by arrival, newest or oldest first, or keep the manual order. The choice is remembered per account and per project, and each card shows how long it has been in its column.
- A card can be grabbed anywhere to drag it, and a card's drawer closes with a click beside it.

## Installing and choosing CLIs

- Installing a CLI from the tour or the new session page shows progress: files received, current file, elapsed time.
- Hide the CLIs you do not use: the "Install" row disappears while the CLI is missing, and comes back with one click.

## Interface

- Right-click a session or project in the sidebar to open its menu, without aiming for the "…" button.
- Selecting text in a table cell no longer spills over into the neighboring cells.
- On Sillage Desktop, creating a project no longer asks whether it is private or shared.
- Claude Code sessions to resume are found even when the case of the path differs from the project's (Windows, macOS).

## Versions and upgrade

Targeted CLI versions unchanged: **Claude Code 2.1.301** (SDK 0.3.301), **Codex 0.163.0**, **OpenCode 1.19.3**, **Grok Build 1.0.62**.

One additive migration since v0.21.0, applied at startup: `0047_card_arrival` (`cards.column_entered_at` and `cards.done_by_merge` columns, two triggers). Keep a backup of your data before updating.
